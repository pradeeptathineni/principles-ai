# Create Content Workflow

Use this workflow only after deterministic bootstrap and after the target domain/subdomain is accepted for content generation.

1. Read the domain manifest, taxonomy review record, and neighboring scope needed for placement.
2. Confirm the target is a universal file or registered accepted subdomain.
3. Use the applicable preset under the shared grammar and allocate location-independent `PRN-......` IDs through the ledger, never from domain/file codes.
4. Follow the research, source, citation, evidence, writing, security, and content standards.
5. Allocate or reuse `SRC-......` records before bibliography use and map each local entry to one stable source ID.
6. Use `[1]` and comma-space-separated runs such as `[1], [2]`, never `[1][2]`; cite every required structural claim unit.
7. Add Applicability, Goals, or Tags only when materially useful.
8. For configured pilot paths, create complete claim-review records under `config/evidence-policy.yaml`.
9. Run deterministic validation, applicable operational checks, semantic evaluation, and human review as separate gates.
10. Report evidence, disagreement, uncertainty, and judgment.

Evidence records are not universally mandatory outside the pilot until a post-pilot human decision changes policy.
